# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PSEye — a free, community-first tracker for the Philippine Stock Exchange (PSE). pnpm + Turborepo monorepo.

## Writing style

Never use em dashes (—) in any user-facing copy: page content, FAQ answers, glossary definitions, metadata descriptions, tweet copy, anything a reader sees. Use a period, comma, colon, or parentheses instead. This does not apply to code comments, which keep the codebase's existing em-dash-heavy documentation convention.

## Commands

Run from the repo root unless noted.

- `pnpm install` — install all workspace deps
- `pnpm dev` — `turbo run dev` (starts `apps/web` on localhost:3000)
- `pnpm build` / `pnpm lint` / `pnpm typecheck` — run across all packages via Turbo (each depends on `^build` first)
- Scope any script to one package: `pnpm --filter @pseye/web <script>` (package names: `@pseye/web`, `@pseye/db`, `@pseye/etl`, `@pseye/source-quotes`, `@pseye/source-news`, `@pseye/source-corporate-actions`, `@pseye/source-block-sales`, `@pseye/source-disclosures`, `@pseye/source-foreign-flow`, `@pseye/treemap-layout`, `@pseye/config`)
- **`DATABASE_URL` precedence.** `apps/web/.env.local` / `etl/.env` (both gitignored) always win over any `DATABASE_URL` inherited from the launching shell — enforced in `apps/web/next.config.ts` and `etl/lib/loadEnv.ts`, scoped to just this one var (a wrong DB fails silently; a wrong secret/API key fails loudly, so those aren't overridden). You no longer need to `Remove-Item Env:DATABASE_URL` before build/ETL commands. `getDailyQuotes` warns if `DATABASE_URL` is set but `daily_quotes` comes back empty, naming the connected host.
- `pnpm db:generate` — Drizzle Kit generate against `packages/db/src/schema.ts`; no live DB needed (diffs against `packages/db/drizzle/`'s migration history).
- **Two databases exist**: local (`apps/web/.env.local`) and prod (GitHub Actions secret). Migrations: `pnpm --filter @pseye/etl migrate-db` applies already-generated SQL to whichever `DATABASE_URL` is active — **not** `pnpm db:push`, whose interactive conflict prompt hangs non-interactively. Prod migrations go through the `db-push.yml` workflow. After adding a migration: run `migrate-db`, then re-run the affected ETL job locally so a new nullable column populates on freshly-inserted rows (it won't backfill existing rows unless that job's upsert uses `onConflictDoUpdate` instead of `onConflictDoNothing` — see `fetch-disclosures.ts`'s `url` column for the pattern).
- ETL jobs (all need `DATABASE_URL`): `fetch-quotes`, `fetch-news`, `fetch-corporate-actions`, `fetch-block-sales`, `fetch-disclosures`, `fetch-foreign-flow`, `fetch-historical-quotes`, `fetch-market-snapshot`, `backfill-company-profiles`, `backfill-company-financials`, `reclassify-news-topics`, `post-daily-tweet`, `migrate-db`. No `fetch-offerings` (the whole offerings feature was deleted 2026-08 — see Architecture). In production these run via GitHub Actions, never on app request.
- **Triggering (2026-08-04): all four cron workflows use `workflow_dispatch: {}` only, no GitHub `schedule:`.** GitHub's native cron queue delays scheduled runs by 2-4h regardless of frequency (confirmed at every cadence tried, from 15-min to once-daily — not just a high-frequency problem), so each workflow is instead called on schedule by an external cron-job.org job hitting its `workflow_dispatch` REST endpoint. If cron-job.org goes down, a workflow simply stops firing — there's no GitHub-native fallback anymore. See git history / each workflow's doc comment for the full investigation if ever revisiting this.
  - `market-data-hourly.yml` — market-snapshot then quotes, sequential steps in one job. Retimed 2026-08-05 from a flat hourly grid to 10 fires tracking PSE's real session boundaries (official times: 9:00 pre-open, 9:30 open, 12:00-1:00 lunch recess/no trading, 2:45-3:00 pre-close/run-off/VWAP, 3:15 close), then doubled same-day to 20 fires (~15 min cadence): 9:35, 9:50, 10:05, 10:20, 10:35, 10:50, 11:05, 11:20, 11:40, 11:55 (pre-lunch), 13:05, 13:20, 13:35, 13:50, 14:05, 14:20, 14:35, 14:55 (run-off), 15:18, 15:30 (settle) PHT, Mon-Fri — one cron-job.org job per fire (cron can't express mixed hour:minute pairs in one schedule). Going to 20 fires required first decoupling ISR cost from fire count: `fetch-quotes.ts`'s `triggerRevalidate` used to force `revalidatePath` on 13 pages every run (would have ~doubled forced ISR writes at 20 fires/day); trimmed to just `/`, with every other page now relying on tag-based lazy revalidation (write-on-next-visit) plus its own 6h wall-clock ceiling instead.
  - `fetch-daily.yml` — news/disclosures/corporate-actions/historical-quotes/foreign-flow as five steps in one job (`continue-on-error` per step; the first four also call `/api/revalidate` on success). Fires 08:20 UTC (4:20pm PHT, right after the 3:30pm close). Block sales is deliberately not included — separate workflow, later PDF publish time.
  - `block-sales-daily.yml` — `fetch-block-sales` alone. Fires 08:00 UTC (~4pm PHT) — a 15-min buffer past the Daily Quotation Report PDF's observed ~07:45 UTC upload. `PseQuotationReportBlockSaleSource` builds the report URL directly from the trade date (`quotationReportUrlForDate`) and walks back up to 7 days via plain HEAD requests — no HTML link-scraping (`pse.com.ph/market-report/`'s report table is client-side AJAX, not present in the raw HTML).
  - `post-daily-tweet.yml` — **fully disabled** (`gh workflow disable`, at user request; re-enable with `gh workflow enable post-daily-tweet.yml`); `workflow_dispatch` still works for a manual run. Also blocked separately by depleted X API billing (see Architecture) — post manually via the `/post-to-x` skill instead, which writes its own `bot_posts` row so this workflow's idempotency check won't double-post if ever re-enabled.
  - `backfill-company-profiles`, `backfill-company-financials`, `reclassify-news-topics`, `migrate-db` — manual/one-off, no schedule. `reclassify-news-topics` recomputes `news_items.topic` for every stored row from its existing title+snippet (DB-only, seconds, no feed fetches) — run it after any edit to the desk lexicon, see the `/news` bullet in Architecture. `backfill-company-financials` scrapes PSE Edge's own "Financial Reports" tab (`/companyPage/financial_reports_view.do?cmpy_id=...`, parsed by `parseFinancialReportsHtml` in `@pseye/source-quotes`) — real Annual Balance Sheet + Income Statement (current vs previous fiscal year), a genuinely different endpoint from the Stock Data tab's own P/E/Book Value/P/BV fields, which are always empty in practice (investigated separately — see `pe-ratio` in `lib/glossary.ts`). Upserts one row per ticker into `company_financials`; rerun yearly after companies file new full-year results, same reasoning as `backfill-company-profiles`. **This table is now also what backs P/E and P/B site-wide** (see `lib/valuation.ts` below), so a stale backfill means stale valuation multiples, not just a stale statements panel.
- `pnpm test` — `turbo run test`. Coverage: `@pseye/source-quotes` (PSE Edge parsers), `@pseye/source-disclosures`, `@pseye/source-corporate-actions` (their PSE Edge HTML parsers), `@pseye/source-news` (ticker tagger, sentiment, desk classifier, story clustering, section relevance, snippet/byline extraction), `@pseye/etl` (foreign-flow PDF parser, tweet-copy builders), `@pseye/treemap-layout` (layout/color math), `@pseye/web` (`lib/dca.ts`, `lib/analytics.ts`, `lib/news.ts`, `lib/valuation.ts`). Scope with `pnpm --filter <pkg> test`.
- **CI**: `.github/workflows/ci.yml` runs `pnpm lint && pnpm typecheck && pnpm test && pnpm build` on every push to `master` and every PR — the only workflow gating code changes. Every other workflow is schedule-only ETL.

## Architecture

Turborepo/pnpm workspaces: `apps/*`, `packages/*`, `packages/sources/*`, `etl`.

- **`apps/web`** — Next.js 16 (App Router) + React 19. Routes: `/` (market map treemap), `/charts` (NASDAQ-only TradingView embed, see below), `/news`, `/calendar`, `/block-sales`, `/disclosures`, `/foreign-flow`, `/dca`, `/stocks/[ticker]`, `/screener`, `/rankings`, `/portfolio`, `/watchlist` (localStorage-backed, `noindex`, excluded from the sitemap — the only version a crawler can see is the empty state), `/sectors`, `/glossary`, `/most-active`, `/analytics`, `/daily/[date]`. Almost all are async Server Components. Rendering (2026-08, ISR Writes quota fix): most pages set `export const revalidate = 21600` (6h) as a safety-net ceiling only — the real refresh is on-demand (see `app/api/revalidate/route.ts` below), so the wall-clock window rarely actually fires. `/stocks/[ticker]` and `/daily/[date]` are `export const dynamic = "force-dynamic"` instead (zero ISR Writes, not just fewer). DCA calculator's interactive core and the Charts page's TradingView widget are client-side. `app/error.tsx` takes `unstable_retry`, not the classic `reset`. **This Next.js version has breaking changes vs. training data** — check `node_modules/next/dist/docs/` before writing Next-specific code (also flagged in `apps/web/CLAUDE.md`).
- **`/charts`** — TradingView's free embeddable widgets refuse to serve PSE-listed symbol data (confirmed across widget types and tickers) — don't re-attempt expecting a config fix. Ticker picker is scoped to a curated NASDAQ list; `allow_symbol_change` still lets a visitor search other TradingView symbols. The widget's own JS overwrites `style.height="100%"` on the element carrying `tradingview-widget-container` — set a fixed height on a wrapper *outside* that class.
- **`apps/web/lib/*.ts`** — shared pattern: DB-backed when `DATABASE_URL` is set and populated, else `Mock*Source`, falling back on any DB error too. Used by `quotes.ts`, `disclosures.ts`, `corporateActions.ts`, `foreignFlow.ts` (index-level and per-stock fall back independently — different ETL jobs), `historicalQuotes.ts` (falls back for *all* requested tickers together, not per-ticker, to avoid blending real and synthetic data in one composite). Keep new features on this same one-fallback-path-per-feature shape rather than instantiating a source directly in a page. `getDailyQuotes()`'s `Quote.price`/`pctChange` are `number | null` — null means no trade to report (suspended ticker, no fill yet); render "N/A", never coerce to 0.
- **`apps/web/lib/valuation.ts`** (2026-08) — P/E, P/B and dividend yield, pure and unit-tested. Surfaced on `/stocks/[ticker]`'s hero rail (with an `FY <year>` hint), as sortable `/screener` columns (defaulting **ascending**, unlike every other numeric column there — cheapest-first is the point of sorting a multiple), and on `/watchlist`. **Two independent guards decide whether a ratio is publishable at all, and neither subsumes the other**:
  - `isPesoDenominated(currencyUnit)` — a handful of PSE issuers file in a foreign currency (Manulife and Sun Life in CAD, IMI/First Gen/ION/OGP/OPM in USD). Caught live during this work: MFC's P/E computed to **811 against a true value near 20, exactly the CAD/PHP rate**, and looked entirely plausible as a number. The scale check below is *structurally blind* to this, because both sides of `netIncome / eps` are in the same foreign currency and it cancels. Only the free-text `currency_unit` string reveals it, so that string is matched against peso markers and anything unrecognized (or null) fails closed.
  - `unitScale(...)` — `parseFinancialReports.ts` deliberately does not normalize `currency_unit` ("PhP (in Millions)" vs "In Thousand Php" vs "PHP"), so the regime is *derived* instead: `marketCap/price` gives real shares, `netIncome/eps` gives implied shares, and their ratio must land within a factor of ~5 of 1, 1e-3 or 1e-6. Tolerance is deliberately loose because those are a current share count vs a prior-year weighted average.
  - Plus a plausibility band (`MAX_PLAUSIBLE_PE`), which is what catches the one case `unitScale` cannot see: a per-share line quoted in the same non-peso unit as the totals stays internally consistent and only the absurd resulting multiple gives it away.
  Verified against the live DB before shipping: 141/282 tickers get a P/E (median 7.2), 182/282 a P/B (median 0.76); the rest are loss-making, un-backfilled, or foreign-currency filers. **If you touch this file, re-run that distribution check rather than trusting the unit tests alone** — the tests cover the logic, not whether PSE Edge's real data still matches its shape.
- **`app/api/history/route.ts`** — Route Handler backing the DCA calculator: the client can't call a real `HistoricalQuoteSource` directly (no CORS to PSE Edge, and it'd mean live-scraping per keystroke), so it fetches this route instead, which reads `historicalQuotes.ts` server-side. Follow this shape for any future interactive client feature needing real per-request data.
- **Portfolio/watchlist integration + promotion (2026-08-08)** — `/portfolio` and `/watchlist` are both localStorage-only, no-account features, previously built independently. Adding a buy calls `watchlist.ts`'s `addWatched` (an idempotent, add-only sibling to the existing `toggleWatched`), so buying a holding auto-stars it. **Deliberately one-directional**: selling does not un-star it, since selling doesn't mean you've stopped wanting to track it. `WatchlistView.tsx` shows a "Held" badge next to any starred ticker that's also a portfolio position. Nav promotion: `NavLinks.tsx`'s `DROPDOWNS` leads with "Tools" (Portfolio first within it, then Watchlist) instead of "Market Data", and `SiteHeader.tsx`'s mobile-only quick-link cluster (previously just Daily Recap) gained a Portfolio icon — Portfolio was deliberately *not* added to the PRIMARY inline row itself, since that row is documented `flex-nowrap` with no spare width between `lg` and `xl`; verified with Playwright screenshots at 1024/1150/1279/1280px that nothing overflows.
- **Portfolio: transaction log + benchmark/risk/dividend-income (2026-08-08)** — `/portfolio` rebuilt from a single {ticker, shares, avgCost} row per position into a real buy/sell transaction log, since "actual portfolio tracker" was the explicit ask. `lib/transactions.ts`'s `computePositions` FIFO-matches the log into current positions (oldest lot sold first) plus a `realizedGains` list; `usePortfolioTransactions.ts` (replaces the old `usePortfolioHoldings.ts`) persists it at the same `pseye:portfolio` localStorage key, upgrading old single-position rows into a synthetic opening buy on read via `migrateLegacyEntries` (dated a fixed `LEGACY_TRANSACTION_DATE` sentinel so it always FIFO-sorts before anything entered going forward) — self-heals to the new format on the next write, no explicit migration step. The derived `positions: Holding[]` still feeds the unchanged `computePortfolioRows` from the prior batch, so day-change/best-worst/sector-allocation/value-history kept working with no changes to that file. Four things layered on top, all in `apps/web/lib/*.ts` + `components/*.tsx`, all pure-function-tested:
  - **Realized P&L** — a "Realized gain (all-time)" stat tile, always shown (even ₱0) once there's any transaction, distinct from the existing unrealized Gain/loss tiles.
  - **Dividend income** (`lib/dividendIncome.ts`) — no new data source: joins current positions onto `lib/dividends.ts`'s existing `getDividendScreener()` rows (the same ttmDividend/nextExDate figures `/dividends` already shows) to project annual income and list upcoming ex-dates for stocks actually held.
  - **Benchmark + risk** (`lib/portfolioBenchmark.ts`, `lib/portfolioRisk.ts`) — reuses `lib/dca.ts`'s `buildCompositeHistory` (the same all-282-ticker equal-weighted PSEi proxy the DCA calculator's composite option already fetches, same cost accepted here) and `lib/analytics.ts`'s `beta`/`correlation`/`alignedReturns` wholesale rather than reimplementing. Portfolio beta is a market-value-weighted average of each holding's own beta, excluding (not zeroing) holdings with too little shared history. `PortfolioCorrelationHeatmap.tsx` is a ticker-axis fork of `SectorCorrelationHeatmap.tsx`'s cell-shading convention, not a shared component (different axis-label shortening needs).
  - **CSV import/export + notes/targets** — `lib/portfolioCsv.ts` (pure parse/serialize, `ticker,type,shares,price,date`, one error message per bad row rather than aborting the whole file) backs `TransactionForm.tsx`'s file-picker import and `TransactionLog.tsx`'s export button. `usePortfolioNotes.ts` is a second, independent localStorage store (`pseye:portfolio-notes`) for a free-text note + target price/stop-loss per ticker — deliberately not part of the transaction log (a note isn't a trade); `PortfolioPositionsTable.tsx` shows a "Target hit"/"Stop hit" badge when the live price crosses either.
  A sell is capped client-side at the ticker's current position size (`sharesHeld`) — `computePositions`' FIFO matcher would silently clip an oversell rather than error, so the form is what actually prevents one being entered. **Hit the same pre-hydration flash `watchlist.ts`'s `useIsHydrated` was built to fix** (confirmed live: a hard reload with real holdings flashed "No holdings yet" for one frame before `useSyncExternalStore` caught up) — `PortfolioTracker.tsx` now gates on that same hook.
- **`/news`** (`app/news/page.tsx`, `components/NewsCard.tsx`, `lib/news.ts`) — an FT-styled section front, not a headline list. Beyond headline/image/ticker/sentiment, each story carries four things added 2026-08-06, all derived at RSS-fetch time in `@pseye/source-news` and persisted (migration 0020):
  - **`author`** — the feed's own `dc:creator`. Only Manila Times, Rappler, Malaya and Inquirer publish one at all; Philstar, GMA and Manila Bulletin send no author field. `cleanAuthorName` does most of the work *rejecting* values, because the field is not uniformly a byline: Inquirer sends editor logins (`clopez`, `jbarrion`) and a robot account (`NewsPublish`), Malaya sends its own masthead and once literally `___`. Rule of thumb encoded there: a single all-lowercase token is a login, a single capitalised one is a wire service.
  - **`topic`** — one of `NEWS_TOPICS` or `"General Business"`, from `classifyTopic`'s keyword lexicon. **Deliberately not the feed's own `<category>` tags**: Manila Bulletin and Manila Times tag every item the constant string `"Business"`, Philstar and GMA send none, so only two of eight outlets could populate a section. Every keyword is anchored at its left word boundary; a trailing space in the keyword additionally anchors the right (`"tax "` must not match "taxi", `"ipo "` not "Iponan", `"reit "` not "reiterate"). Desk order on the page is the fixed `NEWS_TOPICS` order, never today's story count. `"Earnings"` is deliberately listed *before* `"Markets"` and every sector desk, so results reporting stays together regardless of which industry filed it (FT's Companies/Markets split); without that one desk absorbed 22 of 36 stories. **After editing `TOPIC_KEYWORDS`, run `pnpm --filter @pseye/etl reclassify-news-topics`** — the column is written once at fetch time and a story is only re-fetched while still inside its outlet's feed window, so a lexicon change otherwise never reaches stored rows.
  - **`wordCount`** — from `content:encoded` where the feed ships a body, backing "N min read". Null (and the label omitted) otherwise; do not estimate it from the snippet.
  - **Sentence-aware `snippet`** — 340 chars, cut at the last sentence end within `SENTENCE_BREAK_WINDOW`, else at a word boundary. Replaces a fixed 240-char slice that left stored snippets ending mid-word. `lastSentenceEnd` knows decimals (`P8.31`), initials, and an abbreviation list (`Jr.`, `Inc.`), all of which are dense in business copy. A snippet the *outlet* already truncated (arrives with no terminal punctuation) gets a trailing ellipsis.
  `isBusinessRelevant` (`relevance.ts`) then drops what isn't business news at all, by **URL path segment**, not by headline. Three feeds are site-wide despite their names: Malaya's "Business Insight" feed is `malaya.com.ph/feed/`, and 12 of its 14 items in a live sample were an editorial cartoon, a showbiz item or an opinion column. The path is what the outlet's own CMS filed the story under, so it's right by construction where a headline like "Value of naps" is unclassifiable. `/opinion/` as a whole is **allowed** (BusinessWorld and Manila Times file real market analysis there); only unambiguous sub-sections are listed. Matched per whole segment, never as a substring, or `/business/food-and-beverage-giant-posts-record-profit` would die on "food". Applied both at fetch time (so junk costs no og:image fetch or DB row) and in `rankByRelevance` (so rows written before the filter existed are cleaned up, since they'll never be re-fetched).
  - **International wire coverage (2026-08-07)**, `googleNewsSource.ts`/`createGoogleNewsSource`, added because Reuters killed its public RSS feeds around 2020 and Bloomberg/Nikkei Asia never had one — reads Google News' `/rss/search?q=...` endpoint instead, one `site:<domain> "Philippine Stock Exchange"` query per outlet (see `outlets.ts`'s Google News section for full findings). Two things about this endpoint changed since older training data and were re-verified live: **`<link>` no longer 302s straight to the article** — it lands on a `news.google.com` interstitial that only reaches the publisher via client-side JS (confirmed with a real Playwright browser; a plain HTTP client sees only the interstitial), and the base64 in the URL no longer embeds a plaintext URL either, so there's no cheap server-side resolution — stored as-is per explicit sign-off, since a human clicking it still lands correctly after a ~2-3s hop. **`<source>` (the real outlet name/homepage) needs `customFields: { item: ["source"] }`** — unlike `dc:creator`, rss-parser does not map it at runtime unless told to; omitting this silently makes every item's outlet attribution `undefined`. Google's own search here does not `AND` a multi-word query the way a real site search would (an unscoped `"Philippine stock market"` query returned "Low Danube water levels in Bulgaria" from Reuters live), so only the exact quoted phrase is used, and even that occasionally surfaces a stock-quote/company-reference page rather than an article (`isLikelyReferencePage` filters these) since "Philippine Stock Exchange" is also that company's own legal name. AP News was tried and dropped: no query variant returned genuine PSE-specific coverage, only general PH politics/disaster wire copy. Net effect is low, event-driven volume (the exact-phrase query returned zero results inside the 7-day display window when checked) rather than a steady daily beat — expected, not a bug; a real PSE event still gets picked up and, per the ordering/clustering already described above, an international pickup raises that story's score.
  `clusterStories` then collapses one event filed by several outlets into a single card crediting the rest ("Also covered by ..."), by Jaccard overlap on headline tokens within a 36h window. Threshold 0.5 was set against the live feed: below it, two different quarters of one company's earnings merge. **When both stories share a ticker the threshold drops to 0.25**, which is what catches the most visible duplicate on the page: two outlets' versions of one earnings report ("Chinabank net profit up 11% to P14.5B in H1" / "Chinabank's net income climbs 11% to P14.5 billion in first half") score only 0.25, because the shared meaning is in synonyms and in tokens too short to tokenise. Verified against the live 188-story set: 11 merges, all correct, no false positives. A full paraphrase with no shared ticker ("BSP keeps policy rate steady" vs "Central bank keeps benchmark rate unchanged") is a known, tested non-match, and erring that way is deliberate. Ticker chips also carry that stock's move today, joined in from the already-cached `getDailyQuotes` (no extra query); a stock that didn't trade shows a bare ticker, never a fabricated 0.00%.
- **`/news` page structure and `/news/[topic]`** (2026-08-07) — the front page previews, it no longer prints everything. Four blocks, in order: hero + a 3-story rail, a chronological "Latest" strip, and a "Browse by desk" directory of every desk at 3 headlines each. Each desk's full run lives at **`/news/<slug>`** (`app/news/[topic]/page.tsx`, `generateStaticParams` over `NEWS_DESKS`, slugs from `topicToSlug`, e.g. `banking-and-finance`), reachable from a sticky desk nav (`NewsDeskNav.tsx`) that both pages share.
  - **The catch-all desk is now labelled `FALLBACK_TOPIC` ("General Business"), not "More headlines"** — it is a browsable page with its own URL, and a page cannot be titled "more" of something not yet shown. `NEWS_DESKS` = `NEWS_TOPICS` + the fallback, precisely so a story `classifyTopic` could not place stays reachable.
  - **`NewsDeskNav` must be a direct child of the page's tall content column.** Wrapping it in a spacing div sizes its containing block to the nav itself and `sticky` silently stops working (hit during this change); the `mt-4` lives on the nav.
  - **Ordering is a score, not a date sort.** `scoreStory = scoreImportance × 0.5^(ageHours/48)`. Importance is ticker-tagged (+1.4), multi-outlet pickup (+0.9 each, capped at 3 — otherwise one wire story republished by every masthead owns the page), a core desk (+0.7), extra tickers, and a real body. **Every term reads a column that already exists, so the news ETL is unchanged and no new job or workflow was added.** The 48h half-life is what makes the 7-day window mean something: at 24h a week-old story scores 0.008 of fresh (the window is decorative), at 96h yesterday and four days ago are indistinguishable. `rankByRelevance` is now a plain date sort plus the age/relevance filter; its old tagged-then-untagged tiering became the +1.4 term, where it can be outweighed instead of being absolute.
  - **The front-page rail is reserved for market stories**: `pickFeatured` fills it "Markets" desk first, then any ticker-tagged story, then best-scoring. The hero is deliberately exempt, so a major economic story is never demoted under a minor one about a listed company.
  - **Card variants** (`NewsCard.tsx`): `hero`, `lead` (image-on-top, one lede, no kicker since the desk heading is right above it), `secondary`, `compact`, `headline` (no image, no lede, terse byline, no "also covered by"). The directory and the tail of a desk page use `headline`; a stack of full cards is what made the page read as a wall of text.
  - **Feed dates are not trustworthy.** `parsePublishedAt` clamps to now and falls back to now: Inquirer Business stamps up to 3h ahead (8 of 243 live rows), which unclamped monopolised the chronological strip and rendered as "just now" for hours. The fallback for a dateless item is why `fetch-news`'s upsert writes `published_at` with `least(...)` rather than overwriting, which would re-stamp it every run.
  - **`etl/lib/newsPaths.ts`** derives every news route from `NEWS_DESKS`; `fetch-news` and `reclassify-news-topics` revalidate all of them. `revalidateTag("news")` only clears the data cache, not each desk page's own ISR entry, so a desk added to the lexicon without this would serve stale stories up to its 6h ceiling.
- **`app/api/revalidate/route.ts`** — secret-gated (`?secret=` vs `REVALIDATE_SECRET`) on-demand `revalidateTag`/`revalidatePath`, called by `etl/lib/triggerRevalidate.ts` right after `fetch-news`/`fetch-disclosures`/`fetch-corporate-actions`/`fetch-historical-quotes` write new data (generalized 2026-08-01 from an original post-daily-tweet-only call, which is why `tags`/`paths` are optional and default to the quotes-only behavior). `tags` is checked against a closed `KNOWN_TAGS` allowlist rather than passed straight through, since the endpoint is secret-gated but not otherwise authenticated. Also called by `post-daily-tweet.ts` before it screenshots the homepage.
