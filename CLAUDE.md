# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

PSEye — a free, community-first tracker for the Philippine Stock Exchange (PSE). pnpm + Turborepo monorepo.

## Commands

Run from the repo root unless noted.

- `pnpm install` — install all workspace deps
- `pnpm dev` — `turbo run dev` (starts `apps/web` on localhost:3000)
- `pnpm build` / `pnpm lint` / `pnpm typecheck` — run across all packages via Turbo (each depends on `^build` first)
- Scope any script to one package: `pnpm --filter @pseye/web <script>` (package names: `@pseye/web`, `@pseye/db`, `@pseye/etl`, `@pseye/source-quotes`, `@pseye/source-news`, `@pseye/source-corporate-actions`, `@pseye/source-block-sales`, `@pseye/source-disclosures`, `@pseye/source-offerings`, `@pseye/source-foreign-flow`, `@pseye/treemap-layout`, `@pseye/config`)
- **`DATABASE_URL` precedence.** `apps/web/.env.local` / `etl/.env` (both gitignored) always win over any `DATABASE_URL` inherited from the launching shell — enforced in `apps/web/next.config.ts` and `etl/lib/loadEnv.ts`, scoped to just this one var (a wrong DB fails silently; a wrong secret/API key fails loudly, so those aren't overridden). You no longer need to `Remove-Item Env:DATABASE_URL` before build/ETL commands. `getDailyQuotes` warns if `DATABASE_URL` is set but `daily_quotes` comes back empty, naming the connected host.
- `pnpm db:generate` — Drizzle Kit generate against `packages/db/src/schema.ts`; no live DB needed (diffs against `packages/db/drizzle/`'s migration history).
- **Two databases exist**: local (`apps/web/.env.local`) and prod (GitHub Actions secret). Migrations: `pnpm --filter @pseye/etl migrate-db` applies already-generated SQL to whichever `DATABASE_URL` is active — **not** `pnpm db:push`, whose interactive conflict prompt hangs non-interactively. Prod migrations go through the `db-push.yml` workflow. After adding a migration: run `migrate-db`, then re-run the affected ETL job locally so a new nullable column populates on freshly-inserted rows (it won't backfill existing rows unless that job's upsert uses `onConflictDoUpdate` instead of `onConflictDoNothing` — see `fetch-disclosures.ts`'s `url` column for the pattern).
- ETL jobs (all need `DATABASE_URL`): `fetch-quotes`, `fetch-news`, `fetch-corporate-actions`, `fetch-block-sales`, `fetch-disclosures`, `fetch-foreign-flow`, `fetch-historical-quotes`, `fetch-market-snapshot`, `backfill-company-profiles`, `backfill-company-financials`, `post-daily-tweet`, `migrate-db`. No `fetch-offerings` (removed — `offerings` has no real source, see Architecture). In production these run via GitHub Actions, never on app request.
- **Triggering (2026-08-04): all four cron workflows use `workflow_dispatch: {}` only, no GitHub `schedule:`.** GitHub's native cron queue delays scheduled runs by 2-4h regardless of frequency (confirmed at every cadence tried, from 15-min to once-daily — not just a high-frequency problem), so each workflow is instead called on schedule by an external cron-job.org job hitting its `workflow_dispatch` REST endpoint. If cron-job.org goes down, a workflow simply stops firing — there's no GitHub-native fallback anymore. See git history / each workflow's doc comment for the full investigation if ever revisiting this.
  - `market-data-hourly.yml` — market-snapshot then quotes, sequential steps in one job. Retimed 2026-08-05 from a flat hourly grid to 10 fires tracking PSE's real session boundaries (official times: 9:00 pre-open, 9:30 open, 12:00-1:00 lunch recess/no trading, 2:45-3:00 pre-close/run-off/VWAP, 3:15 close), then doubled same-day to 20 fires (~15 min cadence): 9:35, 9:50, 10:05, 10:20, 10:35, 10:50, 11:05, 11:20, 11:40, 11:55 (pre-lunch), 13:05, 13:20, 13:35, 13:50, 14:05, 14:20, 14:35, 14:55 (run-off), 15:18, 15:30 (settle) PHT, Mon-Fri — one cron-job.org job per fire (cron can't express mixed hour:minute pairs in one schedule). Going to 20 fires required first decoupling ISR cost from fire count: `fetch-quotes.ts`'s `triggerRevalidate` used to force `revalidatePath` on 13 pages every run (would have ~doubled forced ISR writes at 20 fires/day); trimmed to just `/`, with every other page now relying on tag-based lazy revalidation (write-on-next-visit) plus its own 6h wall-clock ceiling instead.
  - `fetch-daily.yml` — news/disclosures/corporate-actions/historical-quotes/foreign-flow as five steps in one job (`continue-on-error` per step; the first four also call `/api/revalidate` on success). Fires 08:20 UTC (4:20pm PHT, right after the 3:30pm close). Block sales is deliberately not included — separate workflow, later PDF publish time.
  - `block-sales-daily.yml` — `fetch-block-sales` alone. Fires 08:00 UTC (~4pm PHT) — a 15-min buffer past the Daily Quotation Report PDF's observed ~07:45 UTC upload. `PseQuotationReportBlockSaleSource` builds the report URL directly from the trade date (`quotationReportUrlForDate`) and walks back up to 7 days via plain HEAD requests — no HTML link-scraping (`pse.com.ph/market-report/`'s report table is client-side AJAX, not present in the raw HTML).
  - `post-daily-tweet.yml` — **fully disabled** (`gh workflow disable`, at user request; re-enable with `gh workflow enable post-daily-tweet.yml`); `workflow_dispatch` still works for a manual run. Also blocked separately by depleted X API billing (see Architecture) — post manually via the `/post-to-x` skill instead, which writes its own `bot_posts` row so this workflow's idempotency check won't double-post if ever re-enabled.
  - `backfill-company-profiles`, `backfill-company-financials`, `migrate-db` — manual/one-off, no schedule. `backfill-company-financials` scrapes PSE Edge's own "Financial Reports" tab (`/companyPage/financial_reports_view.do?cmpy_id=...`, parsed by `parseFinancialReportsHtml` in `@pseye/source-quotes`) — real Annual Balance Sheet + Income Statement (current vs previous fiscal year), a genuinely different endpoint from the Stock Data tab's own P/E/Book Value/P/BV fields, which are always empty in practice (investigated separately — see `pe-ratio` in `lib/glossary.ts`). Upserts one row per ticker into `company_financials`; rerun yearly after companies file new full-year results, same reasoning as `backfill-company-profiles`.
- `pnpm test` — `turbo run test`. Coverage: `@pseye/source-quotes` (PSE Edge parsers), `@pseye/source-disclosures`, `@pseye/source-corporate-actions` (their PSE Edge HTML parsers), `@pseye/etl` (foreign-flow PDF parser, tweet-copy builders), `@pseye/treemap-layout` (layout/color math), `@pseye/web` (`lib/dca.ts`, `lib/analytics.ts`). Scope with `pnpm --filter <pkg> test`.
- **CI**: `.github/workflows/ci.yml` runs `pnpm lint && pnpm typecheck && pnpm test && pnpm build` on every push to `master` and every PR — the only workflow gating code changes. Every other workflow is schedule-only ETL.

## Architecture

Turborepo/pnpm workspaces: `apps/*`, `packages/*`, `packages/sources/*`, `etl`.

- **`apps/web`** — Next.js 16 (App Router) + React 19. Routes: `/` (market map treemap), `/charts` (NASDAQ-only TradingView embed, see below), `/news`, `/calendar`, `/block-sales`, `/disclosures`, `/offerings` (unlinked from nav/sitemap, `noindex`, mock-only, direct URL only), `/foreign-flow`, `/dca`, `/stocks/[ticker]`, `/screener`, `/rankings`, `/portfolio`, `/sectors`, `/glossary`, `/most-active`, `/analytics`, `/daily/[date]`. Almost all are async Server Components. Rendering (2026-08, ISR Writes quota fix): most pages set `export const revalidate = 21600` (6h) as a safety-net ceiling only — the real refresh is on-demand (see `app/api/revalidate/route.ts` below), so the wall-clock window rarely actually fires. `/stocks/[ticker]` and `/daily/[date]` are `export const dynamic = "force-dynamic"` instead (zero ISR Writes, not just fewer). DCA calculator's interactive core and the Charts page's TradingView widget are client-side. `app/error.tsx` takes `unstable_retry`, not the classic `reset`. **This Next.js version has breaking changes vs. training data** — check `node_modules/next/dist/docs/` before writing Next-specific code (also flagged in `apps/web/CLAUDE.md`).
- **`/charts`** — TradingView's free embeddable widgets refuse to serve PSE-listed symbol data (confirmed across widget types and tickers) — don't re-attempt expecting a config fix. Ticker picker is scoped to a curated NASDAQ list; `allow_symbol_change` still lets a visitor search other TradingView symbols. The widget's own JS overwrites `style.height="100%"` on the element carrying `tradingview-widget-container` — set a fixed height on a wrapper *outside* that class.
- **`apps/web/lib/*.ts`** — shared pattern: DB-backed when `DATABASE_URL` is set and populated, else `Mock*Source`, falling back on any DB error too. Used by `quotes.ts`, `disclosures.ts`, `corporateActions.ts`, `foreignFlow.ts` (index-level and per-stock fall back independently — different ETL jobs), `historicalQuotes.ts` (falls back for *all* requested tickers together, not per-ticker, to avoid blending real and synthetic data in one composite). Keep new features on this same one-fallback-path-per-feature shape rather than instantiating a source directly in a page. `getDailyQuotes()`'s `Quote.price`/`pctChange` are `number | null` — null means no trade to report (suspended ticker, no fill yet); render "N/A", never coerce to 0.
- **`app/api/history/route.ts`** — Route Handler backing the DCA calculator: the client can't call a real `HistoricalQuoteSource` directly (no CORS to PSE Edge, and it'd mean live-scraping per keystroke), so it fetches this route instead, which reads `historicalQuotes.ts` server-side. Follow this shape for any future interactive client feature needing real per-request data.
- **`app/api/revalidate/route.ts`** — secret-gated (`?secret=` vs `REVALIDATE_SECRET`) on-demand `revalidateTag`/`revalidatePath`, called by `etl/lib/triggerRevalidate.ts` right after `fetch-news`/`fetch-disclosures`/`fetch-corporate-actions`/`fetch-historical-quotes` write new data (generalized 2026-08-01 from an original post-daily-tweet-only call, which is why `tags`/`paths` are optional and default to the quotes-only behavior). `tags` is checked against a closed `KNOWN_TAGS` allowlist rather than passed straight through, since the endpoint is secret-gated but not otherwise authenticated. Also called by `post-daily-tweet.ts` before it screenshots the homepage.
- **`packages/treemap-layout`** (`@pseye/treemap-layout`) — pure layout/color math, no React/DOM (reused by `app/opengraph-image.tsx`). `computeLayout.ts` groups by sector, sizes boxes by market cap (`d3-hierarchy` squarified treemap); any leaf rect that would round to under 1px is nudged out to 1px — a fixed, tested invariant (otherwise a tiny-market-cap stock gets an invisible, unclickable box). `color.ts` builds the diverging red/green `%`-change scale per light/dark mode plus a WCAG-contrast label-ink helper. `ForeignFlowChart` reuses the same convention for net buying/selling.
- **Market map `?filter=`/`?ticker=` URL params** (`MarketMap.tsx`, `TreemapChart.tsx`) sync via `useSyncExternalStore` (custom event + `popstate` — `history.replaceState` alone doesn't dispatch either), server-snapshotting to a default (`"all"`/`null`) so hydration never mismatches on a deep-linked URL. This is what makes a stock/filter shareable via `ShareButton`. **Don't try to make `opengraph-image.tsx` vary per `?filter=`/`?ticker=`** — that convention only receives route `params`, never `searchParams`, and wiring `searchParams` into `page.tsx` flips `/` from static to fully dynamic (confirmed via `next build`) — not worth that cost for a cosmetic improvement. A per-entity share image belongs on its own route instead (see `/stocks/[ticker]`).
- **`app/stocks/[ticker]/page.tsx`** — per-company page (price/%change/ranks, closing-price chart, profile, disclosures, annual balance sheet/income statement, news) over all `PSE_EDGE_COMPANIES` (282 companies). 2026-08: the "Dividends & corporate actions" panel was replaced by a Balance Sheet/Income Statement panel (`CompanyFinancials.tsx`, sourced from `lib/companyFinancials.ts` → `company_financials`) — corporate actions data itself is unchanged and still feeds the page's trailing-12-month dividend yield stat plus `/calendar`, it just isn't listed as its own panel here anymore. The "About {ticker}" profile panel (`lg:basis-2/3`, wider) renders left of the financials panel (`lg:basis-1/3`, narrower) — keep that order and those proportions on future edits. Header also renders `CompanyLogo.tsx` next to the ticker/name when `company_profiles.logo_image` is set. The source URL is extracted off PSE Edge's `companyInformation/form.do` page (`img[alt='Logo']`) during `backfill-company-profiles`, not constructed from ticker/cmpy_id — filename schemes vary across companies (`bdoLOGO1.jpg`, `{cmpy_id}/cl{hash}r{num}.{ext}`, `co_PHES_logo.gif`) with no derivable pattern — but that URL is never stored or served directly: PSE Edge's own logo images are typically a small mark on a large uniform-color canvas (Jollibee's is 614x600 with the mascot occupying a sliver of it, reading as "mostly blank" once shrunk into a UI-sized chip), so `backfill-company-profiles`'s `processLogo` downloads the image and runs it through `sharp`'s `trim()` to crop that padding away, resizes to a 160px max edge, and stores the result as a `data:image/webp;base64,...` string in `logo_image` (`text`, not the old `varchar(512) logo_url` — a data URI runs well past that). `CompanyLogo.tsx` also layers `mix-blend-mode: multiply` on top against its white chip background, so any near-white fill left inside the trimmed frame blends away rather than showing as a hard edge. Renders nothing (not a placeholder) when absent or on image decode failure, same "omit rather than fake it" contract as the rest of this page. Also new in 2026-08: a "Board of directors & management" panel (`CompanyLeadership.tsx`) below the About/financials row, sourced from PSE Edge's separate `directors_and_management_list.do` page (a different endpoint from the one everything else on this profile is sourced from) — stored as `company_profiles.board_of_directors`/`management_officers` jsonb arrays, only rendered when at least one has an entry. `force-dynamic` (2026-08-03, no `generateStaticParams` anymore) — 282 tickers × traffic was the single biggest driver of the ISR Writes quota exhaustion; the underlying `lib/*.ts` DB reads still sit behind their own `unstable_cache` (~1h) so this doesn't mean a live DB hit per request. Reuses existing whole-list lib functions filtered in-memory rather than adding per-ticker queries. Ticker lookup is case-insensitive; canonical `<link>` is always uppercase. `StockPriceChart` only renders when `getHistoricalQuotes` reports `source: "real"` for that ticker, never `MockHistoricalQuoteSource`'s synthetic walk. Has its own `opengraph-image.tsx` and JSON-LD; `app/sitemap.ts` includes one entry per company.
- **`TickerSearch`** (header) — client-side typeahead over the bundled `PSE_EDGE_COMPANIES` roster, no per-keystroke network request.
- **`packages/db`** (`@pseye/db`) — Drizzle ORM schema (`daily_quotes`, `news_items`, `corporate_actions`, `block_sales`, `disclosures`, `offerings`, `index_foreign_flow`, `stock_foreign_flow`, `historical_quotes`, `market_snapshot`, `company_profiles`, `company_financials`, `bot_posts`) + Neon serverless Postgres client (`createDb`) + query helpers (`queries.ts`). `drizzle.config.ts` reads `DATABASE_URL` but `drizzle-kit generate` itself doesn't need a live DB. `daily_quotes.price`/`pct_change` are nullable — see `lib/quotes.ts` above.
- **`packages/sources/*`** — one pluggable source interface per feature: `quotes` (`QuoteSource`, `HistoricalQuoteSource`), `news` (`NewsSource`), `corporate-actions` (`CorporateActionSource`), `block-sales` (`BlockSaleSource`), `disclosures` (`DisclosureSource`), `offerings` (`OfferingSource`), `foreign-flow` (`ForeignFlowSource`). Swap implementations behind the interface; don't change callers.
  - **Real, PSE Edge-backed** (public pages, not a licensed feed; ETL-job-only, never called per-request): RSS news (`createRssSource`); `PseEdgeQuoteSource` (per-company Stock Data pages, delayed/EOD price/%change/market cap); `PseEdgeHistoricalQuoteSource` (real daily OHLC via `/common/DisclosureCht.ax`, needs a `security_id` read off the Stock Data page's dropdown, not just `cmpy_id`); `PseEdgeDisclosureSource` (POSTs `/announcements/search.ax`); `PseEdgeCorporateActionSource` (POSTs `dividends_and_rights_info_list.ax`, Dividends tab only — Rights tab dates are mostly "TBA" placeholders). All key off `@pseye/source-quotes`'s static `PSE_EDGE_COMPANIES` roster (`pseEdgeCompanyDirectory.ts`), matched by `cmpy_id`/`security_id`, not by company-name text (PSE Edge's own strings vary in punctuation/casing).
  - **Real, PDF-backed** (not PSE Edge): index-level foreign flow, block sales, per-stock foreign flow. Live in `etl/lib/`, not `packages/sources/*` — see the `etl` bullet below for why.
  - **Still `Mock*Source`**: `offerings` only. Investigated twice (most recently: disclosure search, SEC Philippines, PSE's own IPO/SRO pages) — no viable free source (SEC PH is fully bot-blocked; PSE's own "Listing Applicants" feed is empty and lacks the required subscription-date fields). Don't re-investigate without new information.
  - `MockHistoricalQuoteSource` takes the *current* quotes as a constructor param (so its anchor price matches whichever `QuoteSource` is live) and floors synthetic close at ₱0.01 (avoids divide-by-zero on sub-centavo tickers in `simulateDca`/`buildCompositeHistory`).
- **`etl`** — standalone `tsx` scripts (no build step), invoked by the GitHub Actions workflows above. Each upserts into Postgres via `@pseye/db`, deduping on a natural key per table.
  - **`etl/lib/pseMarketWatch/`** — `PseMarketWatchForeignFlowSource` (used by `fetch-foreign-flow.ts`), index-level foreign buying/selling from PSE's free weekly Market Watch PDF. Position-based extraction with `pdfjs-dist` (text items grouped into rows by y-coordinate, into columns by x-coordinate) — the raw text stream interleaves the table with footer content, so a naive regex can't separate them. Finding *which* PDF is latest hit the same "client-side AJAX, not present in raw HTML" issue as the block-sales bullet above (2026-08-05: caught live — `index_foreign_flow` had been stuck on one `periodEnd` for weeks because `getLatestIndexFlow()` had quietly been returning null every run, and a null return isn't treated as a job failure). Unlike block-sales' fixed date-based URL workaround, this table has no such predictable path, so the fix instead calls the page's own AJAX endpoint directly: POST `https://www.pse.com.ph/wp-admin/admin-ajax.php` with `action=ptp_load_posts` plus a `_ajax_nonce`/`table_id` pair read off a fresh fetch of `market-report/`'s static HTML (both are short-lived/instance-specific, so they can't be hardcoded) — reverse-engineered from the "Posts Table Pro" plugin's own `posts-table-pro.min.js`. Deliberately doesn't replicate DataTables' per-column server-side search protocol to filter to just "Weekly Market Watch" rows (attempted live; the plugin's PHP handler ignored it) — just fetches 60 unfiltered rows (newest first) and reuses the same `latestMarketWatchLink` regex against their concatenated content, same as it always used against static HTML.
  - **`etl/lib/pseQuotationReport/`** — `PseQuotationReportBlockSaleSource` (used by `fetch-block-sales.ts`), block sales from PSE's free daily Daily Quotation Report PDF, same position-based extraction (the BLOCK SALES table sits between two near-identical PHP/USD header rows). Only the PHP table is parsed. `tradeDate` comes from the filename (`<Month> <DD>, <YYYY>-EOD.pdf`), not a per-row date.
    - Same PDF fetch also feeds `parseQuotationReportForeignFlow` for real per-stock net foreign buying/selling — every MAIN BOARD page has one row per stock; a ticker row is found structurally (ticker-shaped item in the x-range 100–160) rather than by parsing the column header (which is visually split across 3 y-coordinates). Only top/bottom 10 by net value are stored in `stock_foreign_flow`, keyed by the report's real trade date, **written via delete-then-insert per `periodEnd`, not upsert** (it's a top-N leaderboard; `onConflictDoUpdate` would leave a ticker that dropped out of today's top 10 sitting stale next to real rows). `getLatest()` calls `getDocument()` on two separate `pdfBytes.slice()` copies, not one shared buffer — pdf.js detaches/transfers the buffer on use, so a second call on the same `Uint8Array` throws.
  - Both PDF sources share **`etl/lib/fetchWithRetry.ts`** — `pse.com.ph` (not `edge.pse.com.ph`) is a flaky WAF: requests without an explicit `Accept: text/html,application/pdf,*/*` header intermittently 500 regardless of User-Agent. Any new source hitting `pse.com.ph/market-report/` should use this helper, not a bare `fetch()`.
  - **These deliberately live in `etl/lib/`, not `packages/sources/*`**: `pdfjs-dist` has a module-init side effect (a `DOMMatrix` polyfill check) that isn't tree-shakeable through a package's barrel `index.ts` — it broke static generation for every `apps/web` route when tried, even though `apps/web` never calls that code. Any future heavy/native-touching dependency (PDF parsing, image processing, etc.) belongs in `etl/lib/` or its own narrowly-scoped package, never in a `packages/sources/*` package whose barrel `apps/web` already imports for types/mocks. Pinned to `pdfjs-dist@4.0.379` (newer majors need Node ≥22; this repo's tooling is on Node 20). `sharp` (native, used by `backfill-company-profiles.ts`'s logo trim/resize, see the `app/stocks/[ticker]/page.tsx` bullet above) follows the same rule — lives in `etl`'s own `dependencies`, not a `packages/sources/*` package.
  - **`etl/jobs/post-daily-tweet.ts`** — daily market-map screenshot + recap reply to X (`@PSEyeDaily`), scheduled via `post-daily-tweet.yml` (schedule currently disabled, see Commands). Screenshots `#market-map-capture` (a wrapper `app/page.tsx` adds around the kicker/badge/h1/`<MarketMap>`) via Playwright Chromium (`playwright` lives in `etl/`, same dependency-placement rule as `pdfjs-dist` above). **Use `page.screenshot({ clip: boundingBox() })`, not `locator.screenshot()`** — the latter's own scroll-into-view step clips into the top of the content near the sticky header. Idempotency is the `bot_posts` table (`postDate` unique), not an X API read. Tweet copy is pure/tested (`etl/lib/tweetCopy.ts`), with a hashtag-trimming length guard against X's 280-char limit (any URL counts as a flat 23 chars, matching X's t.co). Posts via `twitter-api-v2` (OAuth 1.0a; access token must be generated *after* the X Developer App is set to "Read and Write"). `DRY_RUN=1` composes both tweets and saves the screenshot to `etl/dry-run-market-map.png` (gitignored) instead of calling the X API. Currently blocked from auto-posting: the X Developer Portal project's Pay-Per-Use credits are depleted (`402 credits-depleted`) and a link-containing tweet costs $0.20/request on this tier — post manually instead via the `/post-to-x` skill.
- **`packages/config`** (`@pseye/config`) — shared base `tsconfig.json` extended by every other package.
